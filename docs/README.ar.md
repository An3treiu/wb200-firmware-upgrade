# تحديث البرنامج الثابت لجهاز WB200

**[English — الدليل الكامل](../README.md)** · **[جميع اللغات](../README.md#-languages)**

حدِّث البرنامج الثابت لجهاز HyFix WB200 (مُعدِّن GEODNET) من سطر الأوامر. جرى التحقق منه على عتاد حقيقي: `2.0.33 → 2.0.51`.

> دليل مختصر. المرجع الكامل — جدول نقاط النهاية بالكامل، والتحديث دون اتصال إلى إصدار محدد، وجميع المزالق — موجود في [ملف README بالإنجليزية](../README.md).

## البداية السريعة

استبدل `<IP>` (الافتراضي `192.168.10.1`) و`<SN>` (الرقم التسلسلي) و`<TOKEN>`.

```bash
# 1. اقرأ الحالة واحصل على الرقم التسلسلي — دون تسجيل دخول
curl -s http://<IP>/action/devStatus

# 2. سجّل الدخول — كلمة المرور هي الرقم التسلسلي نفسه. الرد هو الرمز المميز
curl -s -X POST http://<IP>/action/login \
  -H "Content-Type: application/x-www-form-urlencoded" -d "mkey=<SN>"

# 3. ابدأ التحديث
curl -s -X POST http://<IP>/action/ota_online -b "USER=<TOKEN>" \
  -H "Content-Type: application/x-www-form-urlencoded" -d "protocol=ftp"
```

أو دع البرنامج النصي يقوم بكل شيء:

```powershell
.\scripts\upgrade-wb200.ps1        # Windows
```
```bash
./scripts/upgrade-wb200.sh         # Linux / macOS
```

## المتطلبات المسبقة

اقرأ `http://<IP>/action/devStatus` — عام، دون تسجيل دخول — وتحقق مما يلي:

- `inupgrade` = `0`، وإلا فهناك تحديث جارٍ بالفعل
- `wiredIP` = `ONLINE`، أو شبكة WiFi متصلة
- الجهاز لديه اتصال بالإنترنت

القيمة `minerStatus = MINING` هي أقوى دليل على وجود اتصال بالإنترنت، لكنها **ليست شرطًا**. داخل المباني، حيث لا يرى الهوائي السماء بوضوح، لا يغادر المُعدِّن حالة `WAITING` أبدًا — وهذا طبيعي ولا يمنع التحديث.

## ما الذي يحدث

| الوقت | الحدث |
|---|---|
| ~10 ثوانٍ | العثور على البرنامج الثابت على خادم الشركة المصنِّعة |
| ~3–4 دقائق | التنزيل والكتابة — دون أي مؤشر على التقدم |
| بعد ذلك | يعيد الجهاز تشغيل نفسه، وتنقطع الاتصالات |
| ~1 دقيقة | يعود متصلًا، وقيمة `inupgrade` لا تزال `1` |
| بضع دقائق | تصبح `inupgrade` مساوية `0` — انتهى |

> ⚠️ **لا تقطع التيار الكهربائي ولا تفصل كابل الشبكة** أثناء التحديث. فقد يتعطل الجهاز نهائيًا.

## التأكيد

```bash
curl -s http://<IP>/action/devStatus
```

يكتمل التحديث عندما يُظهر `fwVer` الإصدار الجديد **و** تكون `inupgrade` = `0`.

يُبَث التقدم مباشرةً عبر WebSocket على العنوان `ws://<IP>:8080/mcm` — انظر [`scripts/ws-monitor.py`](../scripts/ws-monitor.py). انقطاع الاتصال يعني أن البرنامج الثابت قد كُتب وأن الجهاز يعيد التشغيل؛ وليس خطأ.

## المزالق

- **`/action/debug_ping` يتوقع رمزًا رقميًا (`ping=2`)، لا عنوان IP.** فإذا أعطيته عنوان IP رد بـ `no ip / Get addr error`، وهو ما يبدو وكأنه «لا يوجد إنترنت» لكنه ليس كذلك.
- **يتغير فاصل الإصدار بين الإصدارات:** `WB200_v2.0.33` ← `WB200-v2.0.51`. لا تقارن الإصدار أبدًا بنص ثابت مكتوب في الشيفرة.
- **تبقى `inupgrade` مساوية `1`** لمدة 2–3 دقائق بعد عودة الجهاز إلى الاتصال. وقد يعيد الجهاز التشغيل أكثر من مرة.
- **الرسالة `health: WiFi is not connected!` غير ضارة** عند استخدام الإيثرنت — فالجهاز نقطة وصول وعميل سلكي في آن واحد.
- **لا يمكنك اختيار الإصدار عبر الإنترنت.** خادم الشركة المصنِّعة يقدم دائمًا أحدث برنامج ثابت. وللحصول على إصدار محدد استخدم التحديث دون اتصال الموصوف في الدليل الإنجليزي.

## ⚠️ الأمان

نقطة النهاية `/action/devStatus` عامة وتكشف الرقم التسلسلي — وهو نفسه كلمة المرور. أما رمز الجلسة فليس سوى `base64("user:" + SN)`. عمليًا: كل من يصل إلى الجهاز عبر الشبكة يستطيع إعادة تهيئته أو إعادة كتابة برنامجه الثابت. **لا تعرِّض أبدًا** المنفذ 80 الخاص بالمُعدِّن للإنترنت؛ أبقِه ضمن شبكة محلية موثوقة.
