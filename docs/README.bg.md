# Обновяване на фърмуера на WB200

**[English — пълно ръководство](../README.md)** · **[Всички езици](../README.md#-languages)**

Обновете фърмуера на HyFix WB200 (майнер GEODNET) от командния ред. Проверено на реален хардуер: `2.0.33 → 2.0.51`.

> Кратко ръководство. Пълната справка — цялата таблица с крайни точки, офлайн обновяване до конкретна версия и всички капани — е в [английския README](../README.md).

## Бърз старт

Заменете `<IP>` (по подразбиране `192.168.10.1`), `<SN>` (сериен номер) и `<TOKEN>`.

```bash
# 1. Прочетете състоянието и вземете серийния номер — без вход
curl -s http://<IP>/action/devStatus

# 2. Влезте — паролата Е серийният номер. Отговорът е вашият token
curl -s -X POST http://<IP>/action/login \
  -H "Content-Type: application/x-www-form-urlencoded" -d "mkey=<SN>"

# 3. Стартирайте обновяването
curl -s -X POST http://<IP>/action/ota_online -b "USER=<TOKEN>" \
  -H "Content-Type: application/x-www-form-urlencoded" -d "protocol=ftp"
```

Или оставете скрипта да свърши всичко:

```powershell
.\scripts\upgrade-wb200.ps1        # Windows
```
```bash
./scripts/upgrade-wb200.sh         # Linux / macOS
```

## Предпоставки

Прочетете `http://<IP>/action/devStatus` — публично, без вход — и проверете:

- `inupgrade` = `0`, иначе вече тече обновяване
- `wiredIP` = `ONLINE`, или свързан WiFi
- устройството има достъп до интернет

`minerStatus = MINING` е най-силното доказателство за интернет, но **не е изискване**. На закрито, без чиста видимост към небето за антената, майнерът никога не излиза от състояние `WAITING` — това е нормално и не пречи на обновяването.

## Какво се случва

| Време | Събитие |
|---|---|
| ~10 с | Фърмуерът е намерен на сървъра на производителя |
| ~3–4 мин | Изтеглен и записан — без каквато и да е обратна връзка |
| после | Устройството се рестартира само, връзките падат |
| ~1 мин | Отново онлайн, `inupgrade` все още `1` |
| няколко мин | `inupgrade` става `0` — готово |

> ⚠️ **Не прекъсвайте захранването и не изваждайте мрежовия кабел** по време на обновяването. Рискувате да повредите устройството необратимо.

## Потвърждение

```bash
curl -s http://<IP>/action/devStatus
```

Готово е, когато `fwVer` показва новата версия **и** `inupgrade` = `0`.

Напредъкът се предава на живо през WebSocket на `ws://<IP>:8080/mcm` — вижте [`scripts/ws-monitor.py`](../scripts/ws-monitor.py). Прекъсването на връзката означава, че фърмуерът е записан и устройството се рестартира; това не е грешка.

## Капани

- **`/action/debug_ping` приема числов код (`ping=2`), а не IP адрес.** С IP отговаря `no ip / Get addr error`, което изглежда като „няма интернет", но не е.
- **Разделителят във версията се променя между изданията:** `WB200_v2.0.33` → `WB200-v2.0.51`. Никога не сравнявайте версията с твърдо зададен низ.
- **`inupgrade` остава `1`** още 2–3 минути след като устройството се върне онлайн. Устройството може да се рестартира повече от веднъж.
- **`health: WiFi is not connected!` е безобидно**, когато използвате Ethernet — устройството е едновременно точка за достъп и кабелен клиент.
- **Не можете да избирате версия онлайн.** Сървърът на производителя винаги подава най-новия фърмуер. За конкретна версия използвайте офлайн обновяването от английското ръководство.

## ⚠️ Сигурност

`/action/devStatus` е публичен и разкрива серийния номер — който е и паролата. Токенът на сесията е просто `base64("user:" + SN)`. На практика: всеки, който достигне устройството в мрежата, може да го преконфигурира или препрограмира. **Никога** не излагайте порт 80 на майнера към интернет; дръжте го в надеждна локална мрежа.
